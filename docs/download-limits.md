# 节点下载限速

管理端「节点 → 编辑 → 默认下载限速」设置每份配置的默认值。「用户管理 → 下载限速」可覆盖一个用户在指定平台上的值。单位为十进制 Mbps。用户平台设置正数时优先，即使高于节点默认值。设置 `0` 或留空会清除该层的设置。

| 用户 iOS | 当前节点默认值 | iOS 配置的目标下载上限 |
| --- | --- | --- |
| 10 | 20 | 10 Mbps |
| 0 或空 | 20 | 20 Mbps |
| 10 | 0 或空 | 10 Mbps |
| 100 | 50 | 100 Mbps |
| 0 或空 | 0 或空 | 不限速 |

同一节点上，一份配置的所有连接共享上限。两台设备复用同一份 iOS 配置时也共享额度。其他配置分别计算。上传没有单独的额度。用户换节点后保留其平台设置，未设置时使用新节点的默认值。

## 部署和回滚

1. 按后端项目既有流程备份数据库，针对目标库执行 `pnpm typeorm:gen`，审核生成的 SQL，再执行 `pnpm typeorm:run`，随后部署 API 和管理前端。迁移文件由后端仓库忽略，发布时须针对目标库生成。历史记录的限速字段为空。管理端会标识旧 Agent。
2. 在一个测试节点的长期 `agent.env` 中设置 `AGENT_ENABLE_SPEED_LIMIT=true`。可用 `AGENT_SPEED_LIMIT_INTERFACE=eth0` 指定客户端流量实际经过的出口网卡。留空时要求系统只解析出一个默认出口。
3. 重新部署包含该功能的 Agent 发布包。Bootstrap 会安装所需的 `tc` 和 `nft` 工具，并检查网卡队列。已有自定义队列时，启用会失败并保留现有配置。服务启动并完成预检后，脚本更新受管 Xray 的 webhook。已运行的 Xray 可能在首次启用和关闭时重启，现有客户端需要重连。日常修改速率通过策略同步生效。
4. 在管理端查看配置的**目标下载上限**和节点的**限速服务状态**。`规则已应用` 表示节点已应用该版本的内核规则。悬停可见最近检查时间和错误。启用后可通过 `systemctl status eagleway-speedlimit`、`journalctl -u eagleway-speedlimit` 检查运行情况。本机管理接口为受权限保护的 Unix socket。
5. 回滚时把 `AGENT_ENABLE_SPEED_LIMIT=false` 写回长期 env，然后重新部署同一版或更新的 Agent。确认状态为「未启用限速」后再降级程序。显式关闭会撤销 webhook、停止服务、删除本服务拥有的 nft 表及 HTB 根队列，并检查内核恢复的默认队列。仅停止进程会保留已装载的规则。清理失败时部署会报错，所有权记录会保留以便重试。

## 运行影响

官方 Xray 可执行文件保持原版。独立服务复用 [xray-speedlimit 的 conntrack 实现](../services/speedlimit/UPSTREAM.md)，在指定出口使用一个 HTB 根队列。启用后该网卡的出口调度会改变，新连接需要额外发送一次本机 webhook 并更新连接标记。实际 CPU 和吞吐开销与网卡和连接速率有关。在目标节点记录启用前后的下载、上传、CPU 和延迟，再决定是否扩大范围。

服务为每个 assignment 持久分配标记。当速率清零时，对应的限速类别会被删除。已标记的连接可随策略更新，不必重连。为避免旧连接串用额度，标记不会循环复用。每个节点支持一批最多 10,000 份配置，当前标记格式允许累计 65,534 个不同 assignment。请保留 `/var/lib/eagleway-speedlimit`，里面有持久标记和规则归属记录。

服务故障时 Xray 继续接受连接，已有带标记的连接可能继续按原规则限速。Xray 异步发送 webhook，未送达时不会重投。故障期间新建或漏标的连接可能一直不限速，重连后可重新标记。IPv4/IPv6 的客户端 TCP/TLS 连接均通过外层 TCP 识别，其中可以承载 UDP 代理流量。前置代理复用连接、多网卡分流以及客户端不直接连接 Xray 的拓扑需要单独验证。

## 验收

在测试节点设置节点默认 20 Mbps、用户 iOS 10 Mbps。用同一份 iOS 配置同时下载两个足够大的文件，合计应接近 10 Mbps，另一份未设覆盖的配置应接近 20 Mbps。另测上传。依次清空用户值、清空节点值，并测试用户高于节点默认值。测速时使用足够快的源站，对比基线并给 TCP/TLS 开销留余量。最后关闭服务重测，用 `tc qdisc show dev <网卡>` 核对队列。

仓库的 Linux CI 在临时网络命名空间中验证内核规则的创建、更新和清理，并以指定版本的 Xray 测试并发下载、其他配置、上传和服务重启。发布前仍需在实际目标网卡上测量。
