## 文档维护原则

- 文档描述本仓库当前代码、配置及实际运行行为。旧项目和旧版项目不作为需求参考、实现约束或验证、验收依据。
- 接口说明同时核对本仓库实现和当前对接项目实现；生成 SDK 的输入是当前后端 OpenAPI，生成目录不手工修改。
- “已实现”须有代码入口；“已验证”须有提交或安装包标识、环境、日期、步骤及结果。源码检查、单元测试、构建和真实部署/真机验收分别记录。
- 未经当前版本实测的项目保持“待验证”；发现代码缺陷或契约差异时记录问题，不能仅修改文档将其视为正确行为。
- 当前 API 的 `/api/v1`、数据结构的 `configVersion: 1` 和仍在使用的升级、导入机制按实际含义说明，不按字面删除版本号。
- 历史方案和检查记录放入 `archive/`，不从现行开发、部署及验收流程引用其结论。更新实现时同步更新现行文档。

历史材料仅供追溯，见[归档索引](archive/README.md)。
